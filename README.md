# 文化祭受付システム

文化祭の教室展示(体験型企画・物販など)の**受付と会計を1つの画面で完結させる**Webアプリです。iPadやPCのブラウザから使うことを想定しており、レジ・整理券・混雑状況の把握・売上管理までを一通りカバーします。

## 解決する課題

小規模イベントの受付は、電卓での料金計算・紙のメモによる整理券・口頭での混雑確認など、アナログな運用になりがちです。その結果、

- 会計ミスや行列の発生(繁忙時間帯に計算が追いつかない)
- 「今、教室に何人いるのか」「待ち時間はどれくらいか」が誰にも分からない
- 閉場後の売上集計・記録の突き合わせに時間がかかる

といった問題が起きます。このシステムは、受付での操作を最小限にしつつ、入場・売上のデータが**その場で自動的に記録・共有される**ことでこれらを解決します。複数端末で同時に使っても、データはリアルタイムに同期されます。

## 主な機能

- **レジ会計** — 入場料(大人・学生など)と物販の数量をタップで入力すると合計金額を自動計算。グループ割引は通常料金と自動比較し、安い方を適用
- **整理券** — 満室時は入力内容を整理券として保留し、入場時に呼び出してそのまま精算
- **混雑状況の可視化** — 15分ごとの入場者数の棒グラフと、いま教室にいる人数の目安を示す混雑マップをリアルタイム表示
- **会計履歴** — 確定した会計の一覧表示・修正・削除。日別/全期間のCSV出力(項目ごとに列が分かれ、表計算ソフトでそのまま集計可能)
- **レジ開け・レジ締め** — 金種ごとの枚数入力でレジ内の現金を記録し、売上との差額を自動チェック
- **各種設定** — 料金項目・物販商品・担当者名簿・グラフ表示などを管理画面から変更可能。開催年度ごとにデータを分けて管理

## 画面構成

```
PIN入力(合言葉によるログイン)
 └─ ホーム(開催年度の選択・新規作成)
     └─ ダッシュボード
         ├─ レジ受付   … 会計入力・整理券・直近履歴
         ├─ 混雑状況   … 入場者数グラフ・教室混雑マップ
         └─ 設定       … 料金/物販/担当者/履歴一覧/レジ開け締め/年度管理
```

## 特徴

- **インストール不要** — ブラウザで開くだけ。端末を選ばず、当日借りた端末でもすぐ使える
- **リアルタイム同期** — 受付係とレジ係が別々の端末で操作しても、履歴やグラフは即座に全端末へ反映
- **本番/デモの2環境** — ログイン時のPINによって接続先データが自動で切り替わる。デモ環境で自由に操作練習ができ、本番データには影響しない
- **年度をまたいで再利用可能** — 料金体系や商品が毎年変わっても、コードを変更せず管理画面の設定だけで対応できる
- **運用コストゼロを想定** — Firebase・Vercelの無料枠に収まるよう、データの読み取り量を抑えた設計

## 設計・UI/UXで工夫した点

- **レジ画面は1画面完結** — 繁忙時にスクロールや画面遷移をさせない。数量は大きめの+/-ボタンでタップ入力し、合計と確定ボタンは常に視界に入る位置に固定
- **UI部品の統一** — 日付選択(カレンダー)・時刻選択・確認ダイアログなどはOS標準部品を使わず自作し、全画面で見た目と操作感を統一。ボタンや入力欄の高さ・文字サイズも役割ごとに標準値を定めて統一
- **誤操作への備え** — 設定変更は「変更→画面下部に保存バーが出現→保存/キャンセル」の明示的な保存方式。削除は確認ダイアログ必須、年度データ全削除のような大きな操作は「削除」と入力しないと実行できない
- **グラフの読みやすさ** — 縦軸の上限を固定して日をまたいだ比較を可能に。配色は色覚多様性に配慮した検証済みの組み合わせを使用
- **タイムゾーンに安全な日付処理** — 深夜〜早朝の操作で日付が1日ずれる典型的な不具合を、日付処理の共通関数への集約で防止
- **エラー文言は平易な日本語** — 技術的なエラーメッセージを利用者にそのまま見せない

## 技術スタック

| 分類 | 技術 |
| --- | --- |
| フロントエンド | React 19 / TypeScript / Vite / Tailwind CSS |
| グラフ | Recharts |
| データベース | Firebase Firestore(リアルタイム同期) |
| 認証 | Firebase Authentication(カスタムトークン)+ PIN検証用Serverless Function |
| ホスティング | Vercel |

## ディレクトリ構成

```
api/                  PIN検証用のServerless Function
src/
  components/
    register/         レジ受付画面
    congestion/       混雑状況画面(グラフ・混雑マップ)
    admin/            設定画面(料金・物販・担当者・履歴・年度管理など)
    common/           共通UI部品(カレンダー・確認ダイアログ・保存バーなど)
    layout/           ヘッダー等のレイアウト
  pages/              ページ(ホーム・ダッシュボード)
  hooks/              Firestoreリアルタイム購読などのカスタムフック
  lib/                Firebase初期化・データ入出力・パス定義
  utils/              料金計算・日付処理・CSV生成などの純関数
  types/              ドメインモデルの型定義
firestore.rules       Firestoreセキュリティルール
```

## 実行方法

Firebaseプロジェクトと環境変数(`.env`)の準備が必要です。準備済みであれば以下で起動できます。

```bash
npm install
npx vercel dev   # PIN認証APIを含めたローカル起動
```

```bash
npm run dev      # 画面のみの開発サーバー起動(PIN認証APIなし)
npm run build    # 本番ビルド(型チェック含む)
npm run lint     # Lint実行
```
